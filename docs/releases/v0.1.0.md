# Uzume v0.1.0 — first public preview

Uzume is an independent Neovim distribution for editing code and working with
Codex and Claude Code in isolated Git worktrees. This first preview brings the
editor, agent, review, integration and recovery workflows together. Interfaces
and local state formats may evolve as real-world testing continues.

## What is included

- The Uzume mauve/orange colorscheme, alternative themes, a sidebar explorer,
  floating search and command input, and searchable shortcuts on **Space k**.
- Native **Projects → Windows → Panes** with splits, floating/fullscreen panes,
  keyboard/mouse resizing and optional slide animations. No tmux requirement.
- Extras with curated Rust, Lua, C/C++ and web language packs, user-defined packs,
  Mason tools, diagnostics, formatting and inlay hints.
- Codex and Claude Code terminals on named, isolated task branches. Saved source
  changes are inherited without changing the source checkout or index. Context
  files are marked explicitly, and attention controls help find agents needing input.
- Stable side-by-side/unified review, line comments, feedback delivery, and local
  integration into a chosen branch with labeled conflict resolution.
- Retained-task browsing, guarded removal with recovery snapshots, and guided
  restoration into a new branch and directory. Staged and unstaged changes stay
  distinct. Closing a task stops its agent and retains its files.

See the [feature guide](../features/README.md) and [walkthrough](../../editor/README.md#first-walkthrough).

## Install this release

Install Neovim **0.11+**, Python **3.12+**, Git, ripgrep, fd/fdfind, and a C compiler.
Use a Nerd Font for icons. Then:

```sh
git clone --branch v0.1.0 https://github.com/Memnoc/uzume.git ~/Code/uzume
cd ~/Code/uzume
python3 setup-editor --register
~/.local/bin/uzume
```

Keep this checkout: the configuration links to its `editor/` directory. Registration
creates an isolated launcher/config; ordinary `nvim` and shell startup files are
preserved. Add the launcher directory to PATH, or use the documented
[zsh alias](../features/linux.md#set-up-the-uzume-alias-in-zsh).

For an existing clone, close Uzume and preserve any local configuration edits
before checking out the tag:

```sh
git fetch origin --tags
git checkout --detach v0.1.0
python3 setup-editor --register
```

Never force a checkout over local changes. Older `ai-nvim` installations should
follow the [namespace migration guide](../features/namespace-migration.md) first.
Install the agent CLIs separately and use their own login flows. Language runtimes
and project dependencies are also separate from Mason's editor tools.

## Validation and platform scope

| Environment | Evidence |
| --- | --- |
| Ubuntu 24.04 x86_64, Neovim 0.11.0 | Cache-free source installation, parser/query validation and 28 regression cases in CI |
| Ubuntu 24.04 x86_64, Neovim 0.12.6 | The same installation and regression matrix |
| macOS ARM64 | 28 local regression cases; recovery also exercised on Neovim 0.11.0; fresh installation checked with stable 0.12.6 |

The runtime candidate is `e3abdef`. Its [Linux CI run](https://github.com/Memnoc/uzume/actions/runs/43326063485)
passed both matrix jobs. Release preparation changes documentation only; the
release tag is gated on the final commit's Linux workflow as well.

Tests use real Neovim, Git, PTYs and disposable state. Agent CLIs are fixtures:
automated tests do not make model requests or establish compatibility with every
future vendor CLI release. Manual development and workflow testing used macOS;
hands-on Linux terminal validation is still needed.

## Known limitations

- This is a preview, not a production-support guarantee. Linux ARM64, Intel Mac,
  Windows, musl/Alpine and other desktop/terminal combinations are not verified.
- Neovim is user-installed. Plugin/parser/query inputs are pinned, but there is
  no distribution-managed Neovim or automatic update/rollback UI yet.
- Projects are local. SSH workspaces, debugger/test-runner integrations and
  automatic project-layout autosave are not included. Layout save/restore is explicit.
- Restoring a layout or a recovery snapshot does not restart agents or restore
  their conversations. CLI authentication stays with the vendor tools.
- Integration is local; it does not push, create a PR, or merge upstream.
- Recovery preserves Git content and staging, not a full filesystem backup.
  Unsupported Git states are refused. External writers and other editors'
  unsaved buffers are outside Uzume's locks. Partial operations require inspection.
- Bulk task removal, archive expiry and automatic repair of partial restores are
  deferred. Recovery archives consume local storage until deliberately managed.
- Sustained multi-agent output, animation smoothness, clipboard and mouse behavior
  need more real-world testing, particularly on Linux.

Report issues with the Uzume tag/commit, OS/architecture, `nvim --version`, terminal
version and minimal reproduction steps. Include relevant errors without credentials
or private project content. The next iteration prioritizes bug fixes over features.
